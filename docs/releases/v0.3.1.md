**Concord is research software.** It receives data from acquisition systems and recordings;
it never sends anything to a device. It has been tested in software and with
protocol-level test sources only, **never with acquisition hardware or a participant**, and it
is **not a medical device**. Read [what has and has not been validated](https://github.com/arnavhiteshpatel-cloud/concord/blob/main/docs/VALIDATION_LEVELS.md).

## Download

| File | For | How to open it |
| --- | --- | --- |
| **Concord-macos-arm64.dmg** | Mac with Apple Silicon (M1 or later), macOS 14 Sonoma or later | Open it, drag **Concord** to **Applications**. The app is not signed by Apple: the first time, Control-click it → **Open** (macOS 14), or **System Settings → Privacy & Security → Open Anyway** (macOS 15+). |
| **Concord-linux-x86_64.tar.gz** | Linux on x86_64 with glibc 2.35+ (e.g. Ubuntu 22.04 or later) | Extract it, then open `Concord/Concord` (double-click in a file manager that runs programs, or run it from a terminal). |
| The `.whl` files | Python 3.12 users and developers | Put all wheels in one folder, then `pip install --find-links <folder> "concordos[lab]"`. Add `concord-brainflow` (BrainFlow boards), `concord-bci2000` or `concord-certify` to the same command if you need them. None of these packages is on PyPI. The comparison toolkit alone: `pip install --find-links <folder> concord-hwval`. |
| `SHA256SUMS.txt` | Checking a download | the SHA-256 of every file in this release |

Windows is not supported yet. Each bundle was built and smoke-tested on its platform by the
release workflow before it was published (start, stream a simulated source, record, recover
from a crash, open and quit the window; on macOS also the app run from the mounted `.dmg`).

## What changed since 0.3.0

- **Fixed:**
  - Recording and calibrating from live sources (LSL, Open Ephys, plugins) works; in 0.3.0 it
    failed with "invalid recording name".
  - A recorded decoder's click can now reach the communication board (**Click from** lists every
    running decoder), and **Invert y** is set automatically when needed.
  - The four T15 cursor + click blocks have their own names in the source list, and the source
    card says which file is playing.
  - The empty source list names your datasets folder; the board's input label follows source
    changes; the console shows its version; **Compatibility** works in the app.
  - An export's `REPRODUCE.md` says how to install from the release files (Concord is not on
    PyPI); **Simulator controls** appear only for the simulated profiles; a failed reconnect
    always names its reason.
- **New:**
  - `concord publish …` test streams, for rehearsing without hardware (also from the app's own
    program).
  - The BrainFlow, BCI2000 and certification plugins are included as wheels.
- **Documentation:** the guides are rewritten after an independent first-time walkthrough, with
  new screenshots. Details are in the [changelog](https://github.com/arnavhiteshpatel-cloud/concord/blob/main/CHANGELOG.md).

If you installed 0.3.0, replace it: drag the new **Concord** into Applications (Mac), or extract
the new bundle (Linux). Your data folder is kept.

## What is in this release

- **The operator console** (opens in your browser): connect a source, check signal integrity,
  run a decoder, calibrate, authorize applications to receive commands, record, research
  sessions with export and reproduction, safe stop.
- **Sources:** two simulated devices; recorded human data replayed offline (intracortical
  spiking, ECoG, cursor + click); live streams over Lab Streaming Layer and the Open Ephys
  ZMQ Interface; plugins (BCI2000 included in the app; BrainFlow with the Python install).
- **The communication board**, a participant screen with five input methods.
- **`concord-hwval`**, a toolkit to verify that Concord receives exactly what your
  acquisition software records ([protocol](https://github.com/arnavhiteshpatel-cloud/concord/blob/main/docs/HARDWARE_VALIDATION.md)).

## Known limitations

- Not validated with acquisition hardware or a participant; decoding results are offline and
  open loop only.
- The macOS app is unsigned and not notarized, and has been tested on GitHub's macOS runners
  only, not installed by hand on a physical Mac.
- Concord has no user accounts or encryption: it listens only on this computer
  (127.0.0.1); keep it that way.

All limitations: [LIMITATIONS.md](https://github.com/arnavhiteshpatel-cloud/concord/blob/main/LIMITATIONS.md).
