# Cursor + click decoding and neural-to-communication (T15, offline)

Generated by `python -m brainos.evaluation.run_cursorclick` (2026-11-08T00:09:43Z, 355.4 s). Do not edit by hand.

**Data:** Singer-Clark et al., Dryad doi:10.5061/dryad.prr4xgxzq (CC0), participant T15, day 468. Calibration (Radial8) blocks [0, 1, 2, 6, 7, 8, 12, 13, 14], grid-evaluation blocks [3, 4, 5, 9, 10, 11, 15, 16, 17]; 256 electrodes, 10 ms bins, threshold crossings and spike band power as published (no raw signal is published).

**What this is:** offline, open-loop decoding of recorded closed-loop sessions. During recording the participant controlled the *original* research decoder and corrected *its* cursor. BrainOS's decoders here never had a person in the loop. These numbers say how well BrainOS recovers the recorded intention; they do **not** say how well a person would communicate with BrainOS (that needs a closed-loop study under an approved protocol).

## Protocol

- Hyper-parameters are chosen by leave-one-block-out CV on calibration blocks [0, 1, 2] only, then frozen. Grid block *g* is decoded by a model refitted on the calibration blocks recorded **before** *g* ("recent"), and by the model fitted once on blocks 0-2 ("fixed", the saved demo models). No grid block is ever used for fitting or selection.
- Cursor labels: ReFIT-style intended velocity (the original decoder's speed, pointed at the cued target; zero while the cursor touches it).
- Click labels: the task instruction (attempt a click while the cursor touches the target): on-target bins positive, excluding the first 200 ms on target and the 500 ms after each click; the decision (the command router's click rule: threshold + hold + 1 s refractory + hysteresis) is chosen on out-of-fold probabilities of blocks 0-2.
- Controls: features circularly shifted by half a block against the task; chance levels; the original online decoders' recorded outputs as the reference (historical, not BrainOS).

## Selected models

- Kalman: features `both`, smoothing 0 ms, noise shrinkage 0.1.
- Ridge (baseline): features `both`, smoothing 100 ms, alpha 100000.
- Click: features `both`, smoothing 50 ms, L2 1000; decision P >= 0.9 for 5 bins (40 ms router debounce), 1 s refractory, re-armed when P falls 0.15 below the threshold (the command router's click rule).

*Board integration*: exactly what the communication board does with the stream (cursor starts at the centre, integrated per event, clamped to the grid); this is the chain the end-to-end test drives. *Whole block*: integrated from the block's first recorded position. *Anchored per trial*: the cursor restarts each trial at the recorded position the participant saw (analysis only; recorded positions are never fed to an application). Even the original decoder's own outputs drift when integrated open loop over a whole block (the display loop updated the cursor about every 20 ms and is not exactly reproducible from the published fields); anchored, they reproduce the session.

## Limits

- One participant, one day, open loop. No closed-loop evaluation of BrainOS decoders exists.
- Labels are inferred from the task (intention, click attempt), not observed.
- The original click decoder's timing shaped the trial structure (a click ended the trial), so recall against it is biased against any different decoder.
- Bitrate uses the authors' grid formula on open-loop selections; it is not a communication rate a person achieved with BrainOS.
