Research software in development. No clinical validation. No partnerships. No regulatory clearance. Not a medical device.

Approach

Measure the same things, the same way, whatever the input

Five components, each designed to be checkable by someone other than us. All are research software at an early stage; none has been validated with people.

On this page

1. Task battery

Input-agnostic digital tasks, scored the same way for every modality.

2. Simulated-decoder harness

Controlled input degradation to test the measurements themselves.

3. Home-use logging

Consented, aggregate counts and minutes. Never content.

4. Care-partner capture

Who helped, how, and for how long. Assistance is not failure.

5. Evidence packaging

Raw events, recomputable scores, audit trails.

What it never does

No device control, no decoding, no diagnostic claims.

1. An input-agnostic functional task battery

Version 1 of the battery has 18 original tasks in six families, built from general human–computer interaction and rehabilitation principles. Every input method produces the same canonical event stream, and every task is scored from that stream by the same code. Stimuli are generated once from a seed, so the browser and the simulator present identical layouts.

The battery is experimental. It is not an implementation of the Shirley Ryan AbilityLab Digital Assessment Interface or of any licensed instrument, and it is not a validated clinical outcome assessment.

Metrics, defined in the open

Scores include success, errors and timeouts; movement time; path efficiency; target re-entries and other path measures; Fitts throughput using effective width (ISO 9241-411 style, with validity flags); achieved bitrate; text-entry rate, correct characters per minute and corrected/uncorrected error rates; and task completion for the everyday activities. Every derived metric can be recomputed from the stored event stream. Metric functions only use data a real deployment can record. The full definitions are on the research page.

Timing collected in a browser is reported as selection time, not reaction time, and comparisons are made within the same participant, device, browser and modality. Published hardware validations find browser response times run tens of milliseconds late, with platform-dependent variability.

2. A simulated-decoder harness

Before asking people to spend time on a measure, we want to know whether the measure behaves sensibly. The harness degrades a simulated input channel in controlled, unit-tested ways and runs synthetic “virtual users” through the battery in a closed loop: the virtual user sees the degraded cursor after a feedback delay and corrects for it.

Degradations include gain mismatch and decay, directional bias, white and correlated noise, drift, smoothing, quantisation, reduced update rate, latency and jitter, signal dropouts, temporary loss of control, and missed, delayed or false selections. Virtual users cover velocity-controlled (BCI-cursor-like), position-controlled (mouse-like), gaze-with-dwell and switch-scanning styles.

Questions the harness can answer: does a metric move in the expected direction as input quality worsens? How small a change can it detect? Does it hit a floor or ceiling? How reliable is it on retest under the model’s assumptions?

Simulation is not clinical evidence

The harness is not a model of any device’s physiology or of any patient population. Virtual users are never described as patients, and every simulated record is labelled synthetic. Simulation can show that a metric responds appropriately under defined conditions; it cannot establish reliability, validity or benefit in people. See limitations.

3. Consented, aggregate home-use logging

Whether a device is actually used at home, and for how long, is part of the evidence that is hardest to obtain credibly. NeuroMetric’s home telemetry is opt-in, separately consented, and accepts only aggregate summaries for periods of up to 24 hours: active minutes, number of device sessions, counts of interactions by category (pointer, select, scroll, switch, dwell, and the number of text characters, never the characters themselves), interruptions, and self-reported assistance, fatigue and burden.

A strict allowlist rejects anything else. Payloads that look like content, such as text, URLs, window titles or keystroke arrays, are refused and never stored; only a receipt with reason codes is kept. By default telemetry covers the NeuroMetric application only. No operating-system-level monitoring ships enabled; cross-application measurement exists as documented designs for specific platforms, not as running software.

4. Care-partner and assistance capture

Device activity alone never counts as independence. During tasks, the participant, a care partner or study staff can record assistance as it happens, by type: setup, physical, verbal, troubleshooting, calibration, or task completion. A task completed with help is recorded as assisted, never as failed.

Each task attempt can be placed on an ordered scale, from device unavailable or not connected, through not used, abandoned, completed with another input and completed with assistance, to completed independently. An assistance-weighted completion score exists in the software with fixed, versioned weights; it is labelled experimental until it has been checked against external evidence such as care-partner diaries, observed assistance and licensed independence measures.

Established questionnaires (for example care-partner burden scales) are copyrighted and require licences; NeuroMetric does not reproduce their items without permission.

5. Evidence packaging

  • Canonical input events are stored verbatim with a SHA-256 checksum, so any score can be recomputed and checked.
  • Python is the single scoring source of truth; the browser’s provisional scores are checked against Python reference fixtures.
  • Every record carries its provenance: simulated, replayed or live.
  • Changes to study records are written to an audit trail; consent, withdrawal and retention rules are enforced by the software.
  • Measurement-chain analyses separate within-person from between-person associations and report the assumptions they rely on.

The design is oriented toward the expectations for electronic records in clinical investigations (21 CFR Part 11). It has not been formally validated or qualified, and NeuroMetric does not claim Part 11 compliance.

What NeuroMetric never does

  • No device control. It never sends commands to a BCI, stimulator, eye tracker or any other device. Neuromodulation support is limited to records of therapy sessions and adherence.
  • No decoding. It does not acquire or process neural signals. It sees only what the operating system presents: pointer movements, key or switch presses, selections.
  • No diagnostic or treatment claims. It does not diagnose, monitor disease progression, or recommend therapy changes, and it does not compute clinically important change thresholds.
  • No content capture. No keystroke content, screenshots, messages, passwords or browsing history.
  • No unvalidated composite presented as validated. Experimental indices are labelled experimental.

Regulatory position (analysis, not a legal opinion)

Our reading of FDA guidance is that software which only measures and reports task performance for research, without diagnostic or treatment claims, is likely not itself a medical device, but must still be fit for purpose. Features that interpret data to monitor disease or adjust therapy could change that. No formal determination has been sought.
